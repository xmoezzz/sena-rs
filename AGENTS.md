# AGENTS.md

## Repository expectations

- Target game is Koikake (`恋×シンアイ彼女`) at the user's local game directory. Treat it as read-only. Do not unpack into the game directory.
- Preserve engine-generic PAL semantics. Do not hardcode this game's private variables or line text.
- `Blocked` in `crates/pal-script/src/extsig.rs` means the signature is not fully verified. It does not mean `pal-vm` lacks a handler.
- Run focused tests with `cargo test -p <crate>`. `cargo test --workspace --all-targets` fails in `pal-vm` `nls_config_fixture::startup_config_reads_system_ini_logical_size_before_vm_runs` because `testcase/SYSTEM.INI` is absent (the failure aborts later `tests/` binaries in the same run). `msprite_decodes_first_wmv_frame_from_fixture` is `#[ignore]` without `testcase/movie/opening.wmv`.

## Koikake boot facts

- `ARCHIVE.DAT` is `movie|bgm|mask|em|ev|ev2|etc|bk|se|system|face|voice|st|st2` and lives inside `data.pac`, not as a loose root file. `ResourceManager::bootstrap` searches the `data` base loose first, then `data.pac` (`crates/pal-asset/src/resource.rs`), so an unmodified game root boots. Regression test in `crates/pal-asset/tests/asset_fixture.rs`. `archive_cn.dat` / `archive_tc.dat` remain out of scope.
- There is no `ev2.pac` in this install. A missing search path stays non-fatal (`try_open_in_base` skips absent `.pac` files).
- Root `SYSTEM.INI` is Shift-JIS (engine default; strict decode, no lossy fallback). Logical size is 1280x720, which also matches the engine fallback. The engine reads `def_font_type`, `def_font_effect`, `add_fontname`, `ex_fontname` from the INI — it does not read the `font_size` key (size 28 is the code default). Game values: `DEF_FONT_TYPE = 4`, `DEF_FONT_EFFECT = 1`, `ADD_FONTNAME = default_font`, `EX_FONTNAME = font_ex`; the add/ex names coincide with the engine fallbacks.
- `Script.src` is Sv20, entry `0x1F8`, 4096 points. A real instruction walk finds 67,196 extcalls. `reset_adv` (opcode 25, at `0x2DB70`) was the last unimplemented primary opcode and is now implemented (`crates/pal-vm/src/runtime.rs`); unknown opcodes surface as `UnsupportedCommand` events instead of halting. Opcodes 252 and 253 do not occur, but both have handlers (`wait_frame`, `wait_click`). Opcode names 35 through 262 are a name catalog; this game uses opcode 23 extcalls instead.
- Headless play reaches the title and, after clicking GAME START, the first ADV line. Do not treat a multi-second `wait` as a hang. Harness: `sena --headless` with `--diagnostic-frames`, `--diagnostic-auto-advance`, `--diagnostic-click-when-hit-enabled`, plus per-frame logs and PNG snapshots.

## Implemented since the previous revision

- Movies: `movie_play` decodes MPEG-1 program streams (`plmpeg`) and WMV frame-by-frame; MP4 stays undecoded. Effect-id-1 transitions crossfade the previous PAL frame instead of black. Loop points are honored: WMV rebuilds the decoder then prerolls to `loop_start`; MPEG seeks without reopening; `loop_end` restarts or finishes per loop mode.
- Text: ADV body text renders from the `DEFAULT_FONT.DAT` PAL bitmap font (parsed lookup table, Shift-JIS double-byte slots) when `font_type == 4` and glyphs exist; otherwise the embedded `default.ttf`. There is no system-font path. `def_font_effect` applies a 1px outline. The wait mark renders (EX_FONTNAME sheet as animation frames, triangle fallback). `load_font_ex` still only sets a latch; it now only affects the font_type-4 fallback when the bitmap font is missing.
- `FONT_EX.TGA` geometry is confirmed: the data.pac resource is 88x22, 8-bit grayscale with four horizontal 22x22 frames. The existing square-cell, `frame_count = width / height` path is correct for Koikake.
- Audio: WMA decodes via `wmv-decoder`; `.MIX` playlists are summed/mixed; `BGM.CSV` loop points apply as sample-index loop regions (script start/end overrides win). `app_exec` stays a no-op returning 1 — it must not launch host programs.
- Operands: `MemDatIndirect` reads and writes resolve through the stored direct operand (Game.exe `0x42116b` semantics).
- Save/load: `save` writes original-layout `save/saveNNN.dat` (lock dword, title, mosaic, thumbnail prefix, resume text-command offset at 0x20C) with a `SENARSAV` portable snapshot appended. Thumbnail, mosaic, lock, and copy are implemented. Original-engine saves without the trailer resume by re-entering the script right after the text command recorded at 0x20C with the line rebuilt from the image's text value (0x12A3C) and a re-armed click wait (`import_original_save` in `crates/pal-vm/src/runtime.rs`). The resumable checkpoint refreshes at every parked ADV text command (`adv_wait_checkpoint_pending` is set by text extcalls too, not just `wait_click` — koikake's ADV body is a linear run of text commands), so saves made mid-scene resume at the current line instead of replaying from the savepoint. Portable snapshot format is version 6: button records carry cell size, selected source rect, and color (v4 fix for all-states-at-once buttons), version 5 adds the playing BGM list — a restore stops the outgoing scene's category-4 channels and replays the saved tracks at the top of the next `run_frame` (`replay_restored_bgm`), and version 6 adds each sprite's `native_projection`/`center_scale` — older snapshots restored standing CGs without the logical/1920 draw projection, so characters reappeared 1.5x too large and shifted (the "HiDPI offset" report). Modal menus no longer advance the story: a button click parked on an ADV click wait suspends the wait (`suspend_wait_for_modal`) and re-parks it at the same PC when the menu gosub returns (`take_modal_wait_repark`), and the VM now receives the same button-consumed stripped input as the task system so menu clicks cannot complete work-process click waits.
- Settings: script-side global settings (SYSTEM screen toggles like 選択後スキップ/オートプレイ解除, stored in `system_mem` — kind 0x2, koikake uses `mem_system[53]`/`[54]`, defaults seeded once by point[4044] guarded on `mem_system[0]`) now survive menus and restarts. `memory_stack_push/pop` (category 9 indexes 21/22) no longer roll back `user_mem`/`system_mem`: the native push snapshots only a 0x4000-byte task work bank (ctx+0x1500), and the old portable model restored all three banks on pop, which silently reset every settings change when a menu closed. Cross-restart persistence goes to `save/sena_rs/system_mem.bin` (`SENARMEM` v1, trailing zeros trimmed), written by the `savesystemdata` extcall (category 10 index 25, which the script calls after settings changes) and loaded at boot. This persists more of `system_mem` than the native engine does (native system.dat keeps only the ctx+0x28278 0x800-byte slice = `mem_system[0xCE..0x2CE]` plus its own config block).
- Rendering gaps closed: `get_backbuffer` copies pixels; screen flash renders a fading quad; screen shake applies a decaying render-tree offset; history renders into a sprite and persists with saves (24-entry cap, voice/face kept as raw handles); `graphic.dat` priority (lane × 134), placement offsets, scale, and tint/alpha lanes are applied in `sp_set` (scale skipped for 0/100 dwords).
- Rendering backend: the interactive window renderer composites on the GPU through a real wgpu 29 backend (`crates/pal-vm/src/renderer/wgpu_backend.rs`) — one textured-quad pipeline, per-texture nearest/linear bind groups (linear only when the software path would bilinear-smooth an upscale), half-texel UV inset to keep button cells from bleeding, non-sRGB surface format so blending matches the CPU compositor. The softbuffer compositor remains as fallback when wgpu init fails and can be forced with `PAL_RENDERER=software`. On the GPU path, diagnostic dumps (`--window-dump-frame-at`, `PAL_RENDER_DUMP`) are CPU-rasterized at logical resolution instead of read back. ADV text no longer re-rasterizes per frame: `sync_text_sprite` builds `AdvTextPanelCache` once per text change (base panel + fully rasterized text block + per-line char-x geometry) and the reveal clips those cached pixels at a fractional inside-the-glyph x limit, so the typewriter is a smooth wipe rather than per-character pops; identical frames are skipped via `presented_frame`, and the wait mark only recomposites when its 180ms animation frame changes.
- Web shell accepts a PAL game root (`data.pac` / `SYSTEM.INI` / `archive.dat`).
- Decompiler emits `reset_adv()` and explicit `dynamic_jump(...)` with tests.
- SOUND menu volume control works end-to-end. Four engine behaviors were reverse-engineered from the koikake script disassembly (points 1522/1526/1685/2415-2493) and are required together: (a) generic sprite extcalls accept packed button references `0x02000000 | group << 20 | index` — `sp_get_width`/`sp_get_height` resolve them through the button table, which is how menu scripts measure slider tracks; (b) `btn_slider_set(group, index, travel, axis, value)` positions the knob at `anchor + travel * value / 100` clamped to travel (the fifth argument is the slider value, not an enabled flag — BGM deliberately passes 250 to pin at max because its drag maps full travel to volume 0-40); (c) `btn_on_check(group, index)` returns `-1` once the mouse press ends and non-`-1` while the button holds the mouse (PAL buttons capture on push, tracked as `pressed_button`) — the slider drag loops poll `while btn_on_check(...) != -1`, so the old 0/1 latch deadlocked the menu in an infinite volume-applying loop, which was the "operating the SOUND page corrupts VM state" report; (d) `input_mouse_to_mem` (category 9 index 12) actually writes the live mouse position into the requested temp-mem slots — slider track clicks depend on it. Slider anchors are picked by the neighbour whose sprite sits closest to the knob's offset-zero rest position (`slider_offset` self-validation; plain proximity grabs the adjacent knob and lets the slider run off its track), drag snaps to integral percent, and `bgm_get_volume`/`se_get_volume` return configured percents rather than live (muted/ducked) group levels. `master/bgm/voice/se/voice_ex` volume percents persist through `save/sena_rs/system.ini` alongside the existing mute latches and `SENARMEM` system_mem bank, and boot calls `apply_persisted_audio_levels` after `AudioSystem::new` so restored settings reach Kira before any script volume extcall.
- SOUND menu right side is the per-character voice volume grid, fully script-driven, now rendering: SYSTEM.INI `[sound]` supplies the layout (`MAX_SOUND_UNIT=15`, grid origin/intervals), `Sound.csv` the character registry (`-1`/`-2`/`-3` rows map to `sound_unit_other/male/female`, flag 0 rows stay hidden until the script sets ENTRY_UNIT bits in `mem_system[61]`), and `vo_expos.csv` the per-slot coordinates. Three engine gaps hid it: `sz_buf` never wrote the caller's destination dynamic-string buffer (category 18 index 36 arg[3]) so `open_file` got an empty name and every downstream table read returned garbage; `wsprint` (category 18 index 9) did not parse `%02d`-style width specifiers nor atoi dynamic-string numeric arguments (`save_page%02d`, `save_btn_check%02d`, `sys_scut_menu%02d`, `sound_unit%02d` all load now); and `sz_buf`'s stray echo of its handle into `temp_mem[base+128]` clobbered the unit loop counter, so per-unit positions and names came out as string handles. `get_voice_ex_volume(slot)` / `set_voice_ex_volume(slot, volume, extra)` pop 1/3 args (observed counts) and keep per-character percentages in `voice_ex_volume_percent`.
